# Camps (Phase A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single home with any number of Camps. Arriving at any camp pauses counting, banks carried items, ends
time away and closes the walk with a "Welcome back" recap. Home becomes camp #1.

**Architecture:**

- The device's camps live in the core (`camps.json` in the realm store). `HomeWatch` watches every camp's 50 m circle.
- The engine hands the camp points to the open game, the way it hands zone areas. The game's at-home tests (time away, banking
  on a fix, round trips) become "within 50 m of any camp".
- Kotlin keeps Wi-Fi networks, each now tagged with its camp id, and draws the camps.
- Quest placement still measures from `Game.home`, which becomes each zone's origin in Phase B. So this phase changes no quest
  generation and no slot_data.

**Tech Stack:** Rust core and UniFFI, Kotlin/Compose with MapLibre.

**Spec:** `docs/superpowers/specs/2026-10-15-camps-and-origins-design.md` (Camps section; Origins and zone reach are Phase B).

## Global Constraints

- Game logic and decisions live in the core. Kotlin draws and wraps platform APIs (CLAUDE.md hard rule).
- Events over polling: no timers. GPS is asked for only on events, as `HomeWatch` does today.
- Every colour is a palette token (`ui/Palette.kt`), checked by `scripts/check_color_tokens.sh`. Every string is in
  `ui/HelpText.kt`.
- TDD: write the failing test first; never edit a test to fit the code.
- Conventional commits: subject under 50 chars, body lines at most 72, trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- One circle: `CAMP_CIRCLE_M = 50.0`. It replaces `HOME_CIRCLE_M` (home_watch.rs), `HOME_RADIUS_M` in `game.rs` (100) and
  `HOME_RADIUS_M` in `verify.rs` (100).
  - Kotlin's `NEAR_HOME_M` (75, the Wi-Fi offer) stays separate: it is UI, not a game rule.
- Naming: "Camp" or "camps" in all new code and text. Home is the camp named "Home".
- Commands:
  - `just check-rust`
  - `ANDROID_HOME=~/Android/Sdk just check-android`
  - `just check-hygiene`
  - `bash scripts/android_bindings.sh` after any FFI change

## Rulings (from the code survey, 2026-10-15)

- `Game.home` stays as the quest anchor: the Leash trap, Freeze thaw, the card compass, the fallback quest, forager item
  placement and `pin_at`. Phase B replaces it with per-zone origins.
- Forager banking on a fix (`verify.rs` Collect tracker) happens within 50 m of **any camp**.
- RoundTrip ("come home") quests end at any camp.
- The Away tracker accrues outside every camp.
- `return_home` (slot option) means "return to a camp". Only its help text changes.
- Card and catalog text that says "home" in a presence sense becomes "a camp" ("Bring them to a camp to bank"). Text that means
  the anchor ("away from home", the compass) waits for Phase B.

## Review Focus

1. **Two camps close together** (circles overlap): arriving in the overlap is "at a camp", and leaving needs a fix outside both.
2. **A camp added or removed while away or at a camp:** the state follows at once, the way `set_center` does today.
3. **No camps at all:** Wi-Fi alone decides (today's no-pin path). The game's at-camp tests fall back to `Game.home` with
   50 m, so an engine-less game still works.
4. **Wi-Fi of camp B while the last fix was at camp A:** the state is "at a camp". The name shown follows the Wi-Fi's camp.
5. **First run after the update:** `home.json` migrates to camp "Home" once. A later `set_home` (old callers) updates that
   camp, never a second one.

### Task 1: Camps in the realm store

**Files:**

- Modify: `core/src/realm.rs`. Add `Camp`, `RealmStore::camps`, `set_camps` and the migration. `home()`/`set_home` become
  wrappers over the camp named "Home".
- Test: `core/src/realm.rs` tests.

**Interfaces:**

- Produces:
  - `pub struct Camp { pub id: String, pub name: String, pub point: Point }` (Serialize, Deserialize, Clone, PartialEq, Debug).
  - `RealmStore::camps(&self) -> Vec<Camp>`
  - `RealmStore::set_camps(&self, camps: &[Camp]) -> Result<(), String>`
  - `pub const HOME_CAMP_ID: &str = "home"`.

**Behaviour:**

- Camps are kept in `camps.json` as a list.
- **Migration:** when `camps.json` is missing and `home.json` holds a point, `camps()` returns
  `[Camp { id: "home", name: "Home", point }]`.
  - The first `set_camps` writes `camps.json`.
  - `home.json` is left as it is, since the data is the player's.
  - A missing or corrupt file gives an empty list, never a panic.
- `home()` returns the point of the camp with id `"home"`.
  - When that camp is missing, it returns the first camp's point.
  - With no camps, it returns `None`.
- `set_home(p)` updates the camp with id `"home"`, or inserts it first as "Home".
  - Old callers keep working until Task 4 moves Android to the camps API.

  - A round trip of two camps.
  - `set_home` updates the home camp and never adds a second one.
  - `home()` is `None` with no camps.
  - A corrupt `camps.json` gives an empty list.
- [ ] Run `cargo test -p apgo-core realm::` and confirm the tests fail.
- [ ] Implement.

### Task 2: HomeWatch watches every camp

**Files:**

- Modify: `core/src/home_watch.rs`.
- Test: same file.

**Interfaces:**

- Consumes: `Point`.
- Produces:
  - `pub const CAMP_CIRCLE_M: f64 = 50.0`, replacing `HOME_CIRCLE_M`. Update every user (`engine.rs` `presence_circle`).
  - `HomeWatch::set_camps(&mut self, camps: Vec<(String, Point)>)` replaces `set_center`, and keeps the same "circle changed"
    behaviour.
  - `HomeWatch::circles(&self) -> Vec<Point>`: all the camp centres, only with a walk sensor. Replaces `circle()`.
  - `HomeWatch::has_center` becomes `has_camps` (with the same "and walk sensor" rule).
  - `HomeWatch::camp(&self) -> Option<&str>`: the id of the camp the player is at, when the state is `Home`.
    - Set by the inside fix that arrived, as the nearest camp.
    - Set by `on_wifi_camp(Some(id))` (below).
    - `None` while Checking or Away.
  - `HomeWatch::on_wifi(&mut self, at_camp: Option<bool>, t)` keeps its meaning ("on a camp's Wi-Fi"). Add
    `on_wifi_camp(&mut self, camp: Option<String>, t)`, which records which camp and then calls `on_wifi(Some(camp.is_some()), t)`.
- `HomeState` keeps its variants. `Home` now means "at a camp".

**Behaviour:**

- Inside and outside are judged against the **nearest** camp centre.
  - Outside means more than the fix's accuracy beyond every circle.
  - Inside means fully within one circle, accuracy included.

- [ ] Write the failing tests.
  - Arriving at camp B (two inside fixes) sets `camp() == Some("b")`.
  - Leaving needs a fix outside both of two overlapping circles.
  - `set_camps(vec![])` with no Wi-Fi goes away, as `set_center(None)` did.
  - `on_wifi_camp(Some("a"))` gives `Home` with `camp() == Some("a")`.
  - The existing tests are ported from `set_center(Some(p))` to `set_camps(vec![("home".into(), p)])`. This is a rename of the
    setup only; the assertions do not change.
- [ ] Run the tests and confirm the new ones fail.
- [ ] Implement.
- [ ] Run the tests and confirm they pass. Commit `feat: watch every camp's circle`.

### Task 4: Engine and FFI for camps

**Files:**

- Modify:
  - `core/ffi/src/engine.rs`: feed the camps to `HomeWatch` and to the game; the camps FFI; rename the presence FFI.
  - `core/ffi/src/lib.rs`: records if needed.
- Test: engine tests.

**Interfaces:**

- Produces (FFI):
  - `CampOut { id, name, lat, lon }` and `CampIn` (the same fields).
  - `Engine::camps() -> Vec<CampOut>`
  - `Engine::save_camp(c: CampIn) -> Result<(), CoreError>`: upsert by id. An empty id gets a new uuid.
  - `Engine::delete_camp(id) -> Result<(), CoreError>`
  - `Engine::presence_camp() -> Option<CampOut>`: the camp the player is at.
  - `Engine::presence_circles() -> Vec<CircleOut>`, replacing `presence_circle`.
  - `Engine::presence_wifi_camp(camp_id: Option<String>, t_ms)`, replacing `presence_wifi`.
  - `Engine::bank_at_camp(t_ms)`, replacing `bank_at_home`.
- **Behaviour:**
  - Every camp change re-feeds `HomeWatch::set_camps` and `Game::set_camps` under the game lock (the order is game, then
    watch, as `set_zones` does). It then saves.
  - `set_home` and `home` stay as thin wrappers for one task's time, and are removed in Task 6.
